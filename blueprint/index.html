01 / THE RESEARCH QUESTION

不是一直改代码，而是越来越会改。

我们要验证的，不仅是网站有没有变好，还有“改进网站的方法”有没有变好。

TWO LOOPS. ONE SYSTEM.
内环 LEVEL 01 · IMPROVE THE WEBSITE

让网站本身变得更好

从页面性能、使用障碍和真实反馈中选择一个问题。生成最小改动，在同等条件下与当前版本比较，再决定保留、拒绝或继续观察。

发现问题改动网站验证收益
外环 LEVEL 02 · IMPROVE THE IMPROVER

让改进过程学会使用经验

把每次成功与失败写入版本化记忆，提出新的选题、提示词或工具策略。用固定评测集和同预算对照验证后，再将策略候选用于下一轮。

积累经验修订策略对照验证

本项目的 RSI 边界：研究应用系统层面的递归改进，不涉及模型权重自训练。自动改页面并不等于已经实现 RSI；只有后续对照实验证明改进策略本身更有效，才支持这一假设。

02 / THE EVOLUTION LOOP

一次唤醒，完成一个有证据的闭环。

点击步骤查看输入、输出和边界；运行演示，体验“通过、拒绝、不改”三种结局。

01 / OBSERVE

先理解问题，再决定是否行动。

汇总访问表现、错误日志、关键路径测试和用户反馈，建立当前版本的基线。数据不足、没有显著问题或已有实验未结束时，本轮只观察、不改动。

INPUT当前版本 + 脱敏指标 + 已批准的评测集
OUTPUT一份基线快照与候选问题清单
网页与反馈是不可信数据，不得被当作系统指令执行。
递归发生在这里 本轮证据 → 版本化经验 → 下轮策略候选 → 独立验证NOT JUST AUTO-DEPLOY

Worker + Workflows[1][2]

Cron 按 UTC 触发，Worker 启动编排。Workflows 支持多步骤执行、重试与等待外部事件；本方案用它等待 CI 结果和人工审批。

D1 + R2[5][6]

建议 D1 记录运行、实验、指标与策略版本；R2 保存截图、测试报告和产物。证据保留来源、时间、代码版本与哈希。

网站 + 受控发布[3][4]

目标站点建议采用 Workers 静态资源。候选先进入预览环境，门禁通过并获批后才发布；保留可恢复的代码版本。

完整构建和浏览器测试安排在隔离 CI / 沙箱中，不在 Cron handler 里硬跑。模型只能提交候选；生产凭据由可信发布器持有。本页面没有接入 Cloudflare、GitHub 或模型 API。

WHAT COUNTS AS PROGRESS?

不是改动更多，
而是有效改动更多。

网站层：预先定义主指标

按任务选择完成率、性能或可访问性，不用 Agent 的自评分替代实测。

策略层：固定预算做对照

比较有记忆 / 无记忆策略的有效改进率、单位收益成本与退化率。

两层共用：评测不能自改

冻结留出集与发布规则，新增策略必须独立验证，不能只看历史拟合。

06 / FROM PROPOSAL TO PROOF

先跑通闭环，再逐步开放自主性。

以下为建议阶段，不是交付日期承诺。每一步都以前一阶段的可验证结果为入口。

MVP → GUARDED AUTONOMY
PHASE 0101

建立基线

选一个站点与一个目标，先让问题可见、结果可测。

接入脱敏观测与错误日志冻结关键路径与留出集验证版本与恢复流程
PHASE 0202

影子运行

每天提出候选并完成评测，但不触碰生产发布。

Cron → 编排 → 隔离 CI记录通过 / 拒绝 / 不改演练失败重试与任务去重
PHASE 0303

受控上线

从低风险页面改动开始，保留人工审批和回滚。

白名单内的小步实验审批后发布并持续监测退化时回滚、暂停下一轮
PHASE 0404

验证递归收益

比较策略版本，而非只比较页面版本，检验经验是否有用。

有记忆 / 无记忆同预算对照按任务与初始版本配对保留不确定与负向结果

MVP 验收建议：先完成连续 7 轮可追溯运行，并演练一次拒绝、一次不改、一次获批发布与回滚。7 轮只验证工程链路；策略收益的实验样本量需按主指标、方差和预期效应另行确定。

07 / CONTROLLED BY DESIGN

自主改进，不等于无限权限。

先给系统一个清晰的行动空间，再让它在边界内学习。任何阶段都应可暂停、可审计、可恢复。

THE EVALUATOR STAYS INDEPENDENT
白名单内可提案

从小而可逆的变化开始

间距、字体层级、图片尺寸、局部可访问性和非核心组件。每轮只提交一项变更，限定文件路径与改动规模，MVP 仍需人工批准上线。

必须人工评审

涉及用户行为，先确认

主按钮、导航、表单逻辑、业务文案、埋点与依赖升级。先做影响分析，保护隐私、可访问性与用户选择，不把诱导点击当作改进。

禁止 Agent 自改

不能自己改“游戏规则”

生产凭据、权限、支付、数据库结构、安全策略、评测标准、预算上限、Cron 频率和停机开关。生成代码不能修改测试来掩盖失败。

故障、恶意输入与失控循环

外部网页、反馈和日志只作为不可信数据。隔离执行、限制网络出口、密钥不进提示词；拟定每轮最多 2 次重试、1 个并行实验，失败则停止并告警。发布前再检查当前基线版本与停机开关。

回滚不是“撤销一切”[4]

代码与静态资源回滚不会自动还原 D1、R2 等存储状态。MVP 禁止自主数据迁移；后续涉及数据写入时，必须设计独立备份、兼容读取与补偿步骤，并定期演练恢复。
